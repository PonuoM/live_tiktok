# ตรวจคลิปหลังเรนเดอร์ และวิเคราะห์คลิปคู่แข่ง

## ตรวจภาพก่อนเรนเดอร์ (ทุกครั้งหลังวาดภาพใหม่)

```
node tools/check-shots.js series/<เรื่อง>/episodes/<ไฟล์>.shots.json [--only a,b] [--jobs 2] [--redraw]
```
Sol ดูภาพทีละภาพเทียบกับ prompt ของช็อต, `setRule` และ `docs/set.json` (ถ้าเรื่องนั้นมีไฟล์นี้) ตรวจ 5 ข้อ: camera_side (นอกหรือในกระจก/เคาน์เตอร์), layout, facing (หันหลังต้องเห็นแค่หลัง มือถือต้องเห็นด้านหลังที่มีกล้อง), scale, door
- ภาพที่ไม่ผ่านจะเข้าไปอยู่ใน `.cache/review/<เรื่อง>__<ตอน>.json` ขึ้นต้นด้วย `[auto]` เปิดดูได้ในหน้า Studio
- `--redraw` ย้ายภาพที่ไม่ผ่านไป `_old/` แล้ววาดใหม่ โดยส่งเหตุผลที่ไม่ผ่านต่อให้ `gen-images.js` วาดใหม่ได้สูงสุด 2 รอบ ถ้ามีงานวาดภาพหรือเรนเดอร์ของเรื่องนั้นรันอยู่ จะไม่ย้ายภาพ
- ใช้ราว 35k token ต่อภาพ ผลตรวจเก็บแคชไว้ ภาพที่ไม่เปลี่ยนจะไม่ถูกตรวจซ้ำ
- ภาพที่ผ่านแล้วก็ยังต้องเปิดดูด้วยตาก่อนเรนเดอร์ เครื่องมือนี้ช่วยกรอง ไม่ได้แทนคน
- ถ้าภาพผังร้าน (plate) ขัดกับ `set.md` เอง ภาพที่วาดตามผังนั้นจะผิดทุกภาพ ให้ผู้ใช้ตัดสินว่าจะยึดฝั่งไหน
- เรื่องที่ยังไม่มี `docs/set.json` เครื่องตรวจจะเทียบได้แค่กับ prompt กับ setRule ให้สร้างผังก่อนวาดตอนถัดไปของเรื่องนั้น ใช้ `series/กะศุกร์13/docs/set.md`, `set.json` และ `episodes/plates.shots.json` เป็นต้นแบบ วาดภาพผังเปล่าด้วย `gen-images.js` แล้วเปิดดูทุกภาพก่อนใช้ (ผู้ใช้สั่ง 5 พ.ย. 2026 ให้ทำทุกเรื่อง ทีละเรื่อง)

## ตรวจตอนของเรา (ทำทุกตอนก่อนส่งผู้ใช้)

```
node tools/review-frames.js <วิดีโอ.mp4> [--every 4] [--range 10-40]
```
ผลอยู่ใน `.cache/review-frames/<ชื่อคลิป>/` = `sheet-01.png, sheet-02.png ...` + `report.json`

ขั้นตอน:
- [ ] เปิด `sheet-*.png` ด้วย Read ทุกแผ่น ดูทุกภาพ
- [ ] ลายเส้นตรงกับ `styleRef` ของเรื่อง ภาพไหนเพี้ยนให้วาดใหม่
- [ ] ทิศ: หันหลังต้องไม่เห็นหน้าหรือแว่น จอเห็นเฉพาะเมื่อหันมาทางกล้อง
- [ ] ผังฉากและของประกอบตรงกันทุกภาพ ซับไม่ทับหน้าและอ่านทัน
- [ ] รายงาน: ช่วงภาพค้างเกิน 5 วินาที (กติกาคือเปลี่ยนภาพราว 4 วินาที)
- [ ] ฮุค: เฟรม 0 ต้องสะดุดตา มีภาพขยับภายใน 0.5 วินาที และมีเสียงตั้งแต่วินาทีที่ 0
- [ ] เสียงเงียบเกิน 1.5 วินาทีที่ไม่ได้ตั้งใจ

อ่านผลให้ถูก:
- ภาพนัวร์มักโดนเตือนว่า "มืดมาก" เพราะสไตล์มืดอยู่แล้ว ให้ตัดสินจากภาพจริง
- "ภาพ 0-0.5 วินาที เปลี่ยนน้อย" คือปัญหาจริง ต้องแก้ฮุค
- แสงกะพริบอาจถูกนับเป็นจุดตัดภาพ ถ้าตารางภาพมีภาพเดิมซ้ำหลายช่องติดกัน แปลว่าภาพค้าง ตัวอย่างคือ db01 ที่ 4 วินาทีแรกเป็นภาพมือภาพเดียว

แก้แล้ว: ถ้าความยาวรวมไม่เปลี่ยนใช้ `node make.js <บท> --patch a-b` แล้วรัน review-frames ซ้ำ จากนั้นบอกผู้ใช้ว่าเจออะไรและแก้อะไร

## วิเคราะห์คลิปคู่แข่ง

```
node tools/analyze-ref.js <คลิป.mp4> [--transcribe]
```
ผลอยู่ใน `.cache/ref-analysis/<ชื่อคลิป>/` = `report.md` (ตารางบีต สรุปฮุค 0-3 วินาที) + `sheet-*.png` (ภาพละช็อต) + `report.json`

- `--transcribe` ถอดคำพูดด้วย ElevenLabs ซึ่งกินโควตา ใส่เฉพาะเมื่อต้องการคำพูดจริง
- คลิปตัวอย่างฮุคเดิมอยู่ใน `reference/hooks/` (ยาว 6 วินาที)
- ใช้ผลเทียบจังหวะ: จำนวนจุดตัดใน 1 และ 3 วินาทีแรก ความยาวช็อตเฉลี่ย เวลาที่เสียงแรกดัง แล้วเสนอสิ่งที่ควรปรับในบทของเรา
- ลอกจังหวะได้ ห้ามลอกภาพ ตัวละคร หรือเนื้อเรื่องของคลิปคู่แข่ง
